Measures vs Calculated Columns basics
When to Use Which Interview Fav
Measures are calculated at query time; columns are calculated at refresh time and stored
// Measure — evaluated dynamically based on filter/slicer context, NOT stored in the model
Total Sales = SUM(Sales[SalesAmount])

// Calculated Column — evaluated per-row at refresh time, stored in the model, uses row context
Sales[Profit] = Sales[SalesAmount] - Sales[Cost]

// rule of thumb:
// - use a MEASURE for anything that should respond to slicers/filters (totals, ratios, KPIs)
// - use a CALCULATED COLUMN only when you need the value in a slicer, sort, or relationship
Output
(measures recalculate live in visuals; columns are fixed per row until next refresh)
Variables — VAR / RETURN basics
VAR / RETURN Best Practice
Improves readability and performance by avoiding repeated calculations
Profit Margin =
VAR TotalSales = SUM(Sales[SalesAmount])
VAR TotalCost = SUM(Sales[Cost])
VAR Profit = TotalSales - TotalCost
RETURN
    DIVIDE(Profit, TotalSales, 0)   // DIVIDE handles divide-by-zero gracefully
Output
0.34 (34% margin, or 0 if TotalSales is 0 — no error)
Row Context vs Filter Context context
The Most Important DAX Concept Interview Fav
Almost every DAX bug traces back to misunderstanding this
// ROW CONTEXT — exists inside calculated columns and iterator (X) functions.
// "current row" is known, so you can reference other columns directly.
Sales[LineTotal] = Sales[Quantity] * Sales[UnitPrice]

// FILTER CONTEXT — the set of filters applied by slicers, visuals, or CALCULATE.
// A measure has NO row context — it only "sees" the current filter context.
Total Sales = SUM(Sales[SalesAmount])   // respects whatever filters are active (region, year, etc.)

// CALCULATE converts row context into filter context — this is the bridge between them
Sales Filtered =
CALCULATE(
    SUM(Sales[SalesAmount]),
    Sales[Region] = "East"
)
Output
(Total Sales adapts automatically per visual; Sales Filtered always forces Region = East)
CALCULATE context
The Most Powerful (and Confusing) Function in DAX Interview Fav
Evaluates an expression in a modified filter context
// basic — override/add a filter
East Sales = CALCULATE(SUM(Sales[SalesAmount]), Sales[Region] = "East")

// multiple filter conditions (implicit AND)
East 2026 Sales =
CALCULATE(
    SUM(Sales[SalesAmount]),
    Sales[Region] = "East",
    Sales[Year] = 2026
)

// using a table filter with FILTER for more complex conditions
High Value Sales =
CALCULATE(
    SUM(Sales[SalesAmount]),
    FILTER(Sales, Sales[SalesAmount] > 1000)
)

// REMOVEFILTERS / ALL — ignore existing filters entirely (e.g. for a grand total)
Grand Total = CALCULATE(SUM(Sales[SalesAmount]), REMOVEFILTERS(Sales))
Output
(returns totals scoped to the specified filter overrides)
SUM, AVERAGE, COUNT, DISTINCTCOUNT aggregation
Standard Aggregate Functions Interview Fav
Total Sales      = SUM(Sales[SalesAmount])
Avg Order Value  = AVERAGE(Sales[SalesAmount])
Order Count      = COUNTROWS(Sales)
Unique Customers = DISTINCTCOUNT(Sales[CustomerID])
Max Order        = MAX(Sales[SalesAmount])
Min Order        = MIN(Sales[SalesAmount])

// COUNT vs COUNTA vs COUNTROWS
// COUNT — counts numeric values in a column (ignores blanks/text)
// COUNTA — counts non-blank values of any type
// COUNTROWS — counts rows in a table (most commonly used)
Output
Total Sales: $2,450,000 | Avg Order Value: $158.90 | Order Count: 15,420 | Unique Customers: 3,200
SUMX, AVERAGEX, RANKX iterators (x)
Iterator Functions — Row-by-Row Calculations Interview Fav
Anything ending in X loops through a table row-by-row, then aggregates
// SUMX — multiply two columns per row, THEN sum (can't do this with plain SUM)
Total Revenue = SUMX(Sales, Sales[Quantity] * Sales[UnitPrice])

// AVERAGEX — average of a row-by-row expression
Avg Line Profit = AVERAGEX(Sales, Sales[SalesAmount] - Sales[Cost])

// RANKX — rank each row/category by a measure
Product Rank =
RANKX(
    ALL(Products[ProductName]),
    CALCULATE(SUM(Sales[SalesAmount]))
)

// MAXX / MINX — row-level max/min of an expression
Best Single Sale = MAXX(Sales, Sales[Quantity] * Sales[UnitPrice])
Output
(SUMX/AVERAGEX compute per-row before aggregating; RANKX assigns 1 = top product by sales)
FILTER, ALL, ALLEXCEPT, VALUES filter functions
Table Filter Functions Interview Fav
// FILTER — returns a filtered table, usually used inside CALCULATE
Big Orders = CALCULATE(COUNTROWS(Sales), FILTER(Sales, Sales[SalesAmount] > 500))

// ALL — removes all filters from a table/column (great for "% of total" patterns)
Pct Of All Sales =
DIVIDE(
    SUM(Sales[SalesAmount]),
    CALCULATE(SUM(Sales[SalesAmount]), ALL(Sales))
)

// ALLEXCEPT — removes all filters EXCEPT the ones listed (keep Region, ignore everything else)
Sales Ignoring Product =
CALCULATE(SUM(Sales[SalesAmount]), ALLEXCEPT(Sales, Sales[Region]))

// VALUES — distinct values currently visible in filter context (also useful for checks)
Selected Regions = COUNTROWS(VALUES(Sales[Region]))
Output
(returns filtered/unfiltered totals depending on which filter function is used)
TOTALYTD, SAMEPERIODLASTYEAR, DATEADD time intelligence
Time Intelligence Functions BI Essential
Requires a proper Date table marked as a Date Table in the model
// Year-to-date total
Sales YTD = TOTALYTD(SUM(Sales[SalesAmount]), 'Date'[Date])

// Same period, prior year — for year-over-year comparisons
Sales PY =
CALCULATE(
    SUM(Sales[SalesAmount]),
    SAMEPERIODLASTYEAR('Date'[Date])
)

// DATEADD — shift the date context by any interval
Sales Prior Month =
CALCULATE(
    SUM(Sales[SalesAmount]),
    DATEADD('Date'[Date], -1, MONTH)
)

// PARALLELPERIOD — similar to DATEADD but shifts by whole periods
Sales Prior Quarter =
CALCULATE(
    SUM(Sales[SalesAmount]),
    PARALLELPERIOD('Date'[Date], -1, QUARTER)
)
Output
(each measure recalculates automatically as the report's date filter/slicer changes)
RELATED, RELATEDTABLE, USERELATIONSHIP relationships
Working Across Related Tables Interview Fav
// RELATED — pull a column from the "one" side of a one-to-many relationship
// (used in a calculated column on the "many" side, e.g. Sales -> Products)
Sales[ProductCategory] = RELATED(Products[Category])

// RELATEDTABLE — the reverse: get related rows from the "many" side
Products[OrderCount] = COUNTROWS(RELATEDTABLE(Sales))

// USERELATIONSHIP — activate an inactive relationship for one calculation
Sales By Ship Date =
CALCULATE(
    SUM(Sales[SalesAmount]),
    USERELATIONSHIP(Sales[ShipDateKey], 'Date'[DateKey])
)
Output
(pulls related attributes across the model's star schema)
IF, SWITCH, AND/OR logical & text
Logical Functions Interview Fav
// IF — basic conditional
Sales Tier = IF(SUM(Sales[SalesAmount]) > 10000, "High", "Low")

// SWITCH — cleaner than nested IFs for multiple conditions
Sales Tier 2 =
SWITCH(
    TRUE(),
    SUM(Sales[SalesAmount]) >= 10000, "High",
    SUM(Sales[SalesAmount]) >= 5000,  "Medium",
    "Low"
)

// AND / OR (or use && / ||)
Is Priority Order =
IF(
    AND(Sales[SalesAmount] > 1000, Sales[Region] = "East"),
    "Yes", "No"
)
Output
(returns tiered labels based on measure/column values)
CONCATENATE, FORMAT logical & text
Text & Formatting Functions
// concatenation — & operator is more common than CONCATENATE()
Full Label = Products[ProductName] & " - " & Products[Category]

// FORMAT — turn a number/date into a formatted string
Formatted Sales = FORMAT(SUM(Sales[SalesAmount]), "$#,##0.00")
Formatted Date  = FORMAT('Date'[Date], "MMM YYYY")

// dynamic label that changes with slicer context — common KPI card pattern
KPI Label =
"Sales for " & SELECTEDVALUE(Products[Category], "All Categories")
Output
Full Label: "Widget A - Hardware" | Formatted Sales: $2,450,000.00 | KPI Label: "Sales for Hardware"
% of Total common patterns
Percent of Grand Total Very Common
Pct Of Total Sales =
VAR CurrentSales = SUM(Sales[SalesAmount])
VAR GrandTotal = CALCULATE(SUM(Sales[SalesAmount]), ALL(Sales))
RETURN
    DIVIDE(CurrentSales, GrandTotal, 0)

// format as percentage in the visual, or wrap with FORMAT():
Pct Of Total (Formatted) = FORMAT([Pct Of Total Sales], "0.0%")
Output
0.238 (23.8% — recalculates per row/category in a matrix visual)
Running Total common patterns
Cumulative Total Over Time Very Common
Running Total Sales =
CALCULATE(
    SUM(Sales[SalesAmount]),
    FILTER(
        ALL('Date'[Date]),
        'Date'[Date] <= MAX('Date'[Date])
    )
)
Output
(accumulates day-over-day / month-over-month depending on the visual's date grain)
Year-over-Year Growth common patterns
YoY % Growth Very Common
Combines time intelligence with DIVIDE for a safe percentage
Sales YoY % =
VAR CurrentYear = SUM(Sales[SalesAmount])
VAR PriorYear =
    CALCULATE(
        SUM(Sales[SalesAmount]),
        SAMEPERIODLASTYEAR('Date'[Date])
    )
RETURN
    DIVIDE(CurrentYear - PriorYear, PriorYear, 0)
Output
0.12 (12% growth vs. same period last year, or 0 if there's no prior-year data)
